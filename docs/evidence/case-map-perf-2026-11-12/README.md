records (300 / 3,000), frame memberships with one "hub" person placed in every question's and action's frame

## Hot spot found and fixed

The whole-case package export was the slowest operation (≈ 89 s for the 57 MB stress package). The prepare step read the
finished HTML in full — including rebuilding every section's visible text with regular expressions — only to look for
active content, and the read-back of the written file rebuilt the section texts it never uses. Now prepare calls only the
active-content check (`CasePortablePackageReader.violations`), the tag-by-tag `javascript:` scan runs only when the page
contains that text, and the read-back skips the section texts (`read(_:sectionText: false)`). The checks themselves are
unchanged. Measured on the normal case: prepare 2,889 → 2,067 ms, write + read-back 1,947 → 1,363 ms (≈ 29–30 %). **The
stress case was not re-measured after the fix** (a stress run takes ≈ 25 minutes, ≈ 21 of them seeding).
