## Cause and fix: intentionally changed behaviour

PERF-25 made `BackupService.staged` keep its hidden staging folder (`.<name>.writing-resume`) when a write fails, as long as the folder holds a copy resume log. The next backup to the same place then copies only what is missing.

Whether the log exists when the write fails depends on whether a file finished copying before the bad input was reached. The copies run in parallel, so this varies: the test passed locally and failed on CI.

The test now checks:
- the earlier backup still verifies and is untouched;
- no `.replaced-` folder is left;
- if a staging folder stays, it is only the hidden `.Backup.writing-resume` folder, and it carries its resume log;
- after a successful rewrite, no staging or replaced folder remains.

Marked "Updated for PERF-25 (owner 2026-11-22/23)". No privacy, consent or erasure assertion was weakened.
