## Causes and fixes

### Code defects (the code was fixed)

- **ShardMerger, F28 ratchet.** The S2 shard fold (`foldClashes`) used raw `execRaw("SAVEPOINT …")`. It now runs in `Database.withSavepoint("shard_fold")`. Behaviour is the same: the update and `changes()` run inside the savepoint, and a throw rolls back and is logged as "not folded".
- **EmailLoader, ScaleRun.** Thread merge became the default in S4 (74ebaa8e). The mbox thread-plan pass, and the per-thread build, decoded every message inside one concurrency job with no autorelease pool, so Foundation temporaries piled up for the whole mailbox. The per-message stream already had this fix (W0-1). Both loops now use one `autoreleasepool` per message or thread. Re-run: the mailbox and SQLite scale tests pass.
- **CasePartReplies, PERF-22 (found while checking the speed commits).** The store is process-wide, and every AppState booted in the test host sets it. Because of this, a test's case read kept and reused replies in another test's ledger. CaseWholeReadingTests/consentOncePerDocumentSet then saw 2 sends instead of 4. In the test host, only a test's own task-local `CasePartReplies.TestOverride.store` is now used (nil = nothing kept), the same pattern as `CaseBatchJournal`. The app is unchanged.
