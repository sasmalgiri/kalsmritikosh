# Speed benchmark (PERF-33) — small

Generated by `KalsmritikoshTests/SpeedBenchmarkTests.swift` over the generated corpus of `KalsmritikoshTests/Support/SpeedBenchCorpus.swift` in a throwaway ledger (never the owner's).

> **Baseline, before the speed fixes (PERF-21 … PERF-32).** Run 2026-11-23 00:53 IST with `RunSomeTests` (trigger file
> `build/perf/RUN_SPEED_BENCH` = `small`), cut from the console with the `===SPEED_BENCH_BEGIN/END===` markers; the
> generated corpus and ledger were removed by the run. The **small** size was used: the import alone took ~5 minutes, so
> the medium corpus (2,000 documents, 50 MB mailbox) would not fit the ~10-minute budget on this Mac. The load average
> was 9–10 on 10 cores (other sessions running), so timings over-state the cost; compare after-runs at a similar load.
> `ledger MB 0.0` was not read correctly by this run (PRAGMA page count); the harness now reads the file size.
> HNSW and IVF each indexed 752 of the 1,010 stored vectors; why 258 were skipped was not investigated here (IVF skips rows whose stored size does not match the dimension).

## Limits

- Debug (unoptimised) test host in the XCTest process, not a signed Release app; one run, no repeats.
- The boot ran with suppressAutoReingest (the eval isolation), so no boot-time maintenance overlaps the phases; the import's own after-work does run.
- Peak footprint is the whole test process (phys_footprint sampled every 250 ms), not the phase alone.
- The AI phase uses a scripted helper stand-in (300 ms per request); no network was used.
