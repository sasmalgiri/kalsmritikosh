# UI journeys — acceptance case (supplier alleged to be paid twice) — 2026-10-31 (run e)

Re-verification of the run-d fixes (commit `933cedb3`) through the real macOS UI via the Accessibility
API. Same method as run d: AX tree dump, AXPress by identifier/title/frame, backgrounded AXPress +
hit-test (`AXUIElementCopyElementAtPosition`) for menus and popups, AX set-value for AppKit panel
fields, `⌘⇧G` in the save/open panels, `screencapture`. One addition to the driver (source saved here
as `axdrive-main.swift`, compiled with `swiftc` to `/tmp/axd2`): a `setsel` command that inserts text
through `kAXSelectedTextAttribute` after AX-focusing the field, so SwiftUI bindings update without any
keyboard event (see harness note 2 for why). A 20-line helper `winid-main.swift` lists the app's
window IDs so screenshots could be taken with `screencapture -l <windowID>` (harness note 3).
Everything below is what was observed, not what should have happened. No source file was edited; no
commit was made.

Harness notes (not product defects):

1. **A peer session was running LawyerFleet UI tests on the same desktop for the whole run**
   (`LawyerFleetUITests-Runner` + a `LawyerFleet` instance relaunched every few seconds, pids 65008 →
   65032 → 65138 → 65743 → 65996 …). Each relaunch made LawyerFleet the frontmost app, so keyboard
   events were unreliable: a `Return` sent after a positive front-check did not reach the Go-to sheet
   (01:37:25), and one `cmd+a` + typed "Dalmia Traders payment" (01:42:0x) went to LawyerFleet after
   it took the foreground between the check and the keystrokes (the text may have landed in whichever
   LawyerFleet field was focused — disclosed to the owner here; nothing in this app was affected,
   the title field was empty afterwards and was refilled through AX). From 02:02 on, **no keyboard
   event was used for text**: all text went in through `setsel` (AX selected-text insertion) and all
   buttons/menus through AXPress / hit-test press. The only keyboard events after that were two
   `⌘⇧G` in the save panel (front-checked, both reached the panel) and one `Return` after a mouse
   click into the Go-to path field.
2. Plain `AXUIElementSetAttributeValue(kAXValue)` on a SwiftUI `TextField` shows the text but does
   **not** update the binding ("Start matter" stayed unavailable after it). `kAXSelectedTextAttribute`
   does update the binding (every field in this run: matter title, hypotheses, evidence, ACH quote,
   allegation, allegation quote).
3. Because LawyerFleet's window sat over the middle of the screen, **every full-screen
   `screencapture -R` from step 2 on showed LawyerFleet's window on top of this app** (the AX text was
   read from this app regardless). Those captures were deleted and the states re-captured with
   `screencapture -l 23083` (window-ID capture renders the window even when occluded) before quitting;
   the two ACH notices that cannot be re-captured without redoing the action (the "Filed under…" notice
   and the Export notice) are recorded as AX text only. "Copy report" and "Print" were repeated once
   at 02:21 for their captures; that added case-log line #9 (see step 4d).
4. The Claude harness' command hook timed out six times (~10 min each: 00:5x–01:1x, 01:21–01:31,
   01:42–02:02, 02:10–02:20). The wall-clock gaps in the timestamps are the harness, not the app.
   `screencapture` run in the foreground also hung the shell after writing the file, so it was
   backgrounded.
