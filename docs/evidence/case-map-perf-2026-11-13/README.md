## Bug found and fixed: ingestion ran on the main thread (PERF-05)

The app target isolates undeclared types to the main actor (`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`). Every
structural parser, loader and pipeline helper (`StructuralParser.parse`, `Ingestor.ingest`, `UniversalParserPlugin.execute`,
the cleaner, chunker, classifier, entity/event extractors, content-surface projector, byte capture, OCR helper, intake
and completion services) was therefore main-actor code: each file's parse ran on the main thread, and the bounded
fan-out (40 files in flight, 9 CPU lanes) was serialised behind it. A sampled stack showed `TypedFieldExtractor`
(via `ContentSurfaceProjector`) holding the main thread. S17 marks the requirements and their conformers `nonisolated`.

| Same 200-file intake, normal case | Before | After |
|---|---|---|
| Intake wall time | 538 s | **57 s** |
| Parse/OCR, cumulative | 544 s | 58 s |
| Per file p50 / p95 / max | 101 ms / 24.8 s / 65 s | 95 ms / 660 ms / 43 s (one OCR image) |
| A 120-page PDF ingested: longest main-thread hold | 1,790 ms of a 2,231 ms ingest | ≤ 101 ms over 8 PDFs (≈ the test's own PDF drawing) |

The fix exposed a second bug, also fixed: off the main thread a `URL`'s cached resource values are never flushed by the
run loop, so a file rewritten under the same URL read its old size and date and was refused as "changed during capture"
(`CanonicalSourceIntakeRepositoryTests.changedBytesNewVersion`, `DurableReadinessIngestTests.oldVersionCoverageUnchanged`).
`SourceByteCapture` and `SQLiteAcquisition` now read fresh values.

## Tested sizes and explicit limits (PERF-11)

Tested: the two workloads above on this Mac. The stress case (5,000 documents, ~55,000 records, ~62,000 links) is usable:
400 items drawn with 2,392 held back and disclosed, every record reachable in 86 list pages, 4 groups, 60 levels of the
long branch opened, the hub one record in 450 frames, 0 positions moved; its whole-case package was 97 MB (prepare 91 s,
write + read-back 38 s). Larger cases are not refused but are untested.

S17 found and removed two silent caps: a report's rule reader (`reportPassages`) and a point's source-sentence check
read at most 20,000 passages of a document and dropped the rest without saying so; both now read every passage
(`SmartMapS17Tests.longReportReadInFull`, 20,050 passages). Every non-literal cap in the case map, case file and case
search is now listed with how it discloses the rest, and a source guard fails on a new one
(`truncationPointsAreInventoried`); 15 literal SQL row caps elsewhere in the app are inventoried but were not audited
for disclosure.

## Disk pressure (PERF-08)

Parser temporary copies (DOCX, PPTX, XLSX, ODS, ODT, EPUB, image readers), an archive's whole expansion, and each archive
member's extraction are refused before writing when the temporary folder's volume cannot hold them plus 64 MB. The
refusal is the recorded failure of the item, with what it needs, what is free and three safe choices (free space and
process again; add it later on its own; leave it unprocessed), and the custody record and the original stay untouched.
Not guarded: PDF page images rendered for OCR, email attachment staging, video frames — a full disk there fails that
write with its own recorded error. No recovery screen was built (GUI); not observed under a real full disk.
