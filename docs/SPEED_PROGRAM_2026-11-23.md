# Speed program: download-manager techniques across the app (owner, 2026-11-23)

The owner asked for five download-manager techniques to be applied to every process that handles a lot of data:

1. **Segmentation with work stealing.** Split the work into pieces; an idle worker takes half of the largest remaining piece.
2. **Resumable progress for each piece.**
3. **Throughput-tuned concurrency.** Add workers while throughput rises, back off sharply when it drops or on a 429, and always stay within the memory budget (WorkerBudget).
4. **Large sequential reads in one pass.** Hash while reading, use big buffers, compute once and reuse, page by key instead of OFFSET, and avoid N+1 queries.
5. **Reused connections.** Keep connections alive and multiplex them; resolve the provider once.

Three read-only sweeps of the code on 2026-11-23 found about 145 places, covering:
- Ingestion, Storage, Core, Sync, Forensics, Export and Workers;
- Knowledge, Brain, Retrieval and EvalKit;
- App, Investigate, Personas, Workflow, UI, Routing, the network helper, Share and the relay.

They are grouped below into tracker rows PERF-21 … PERF-33 (spec ref `SP-2026-11-23`). Code that is already parallel or resumable stays as it is: PipelineStages, ShardMerger, IngestWorkerPool, PDF page ranges, system-archive members, `SourceByteCapture`, `EvidenceVault.storeStreaming`, keyset `CaseBriefingRepository` / `ClaimProjectionBackfill` / `ChunkDerivation.verify`, CoreML tokenising, the Reranker batch, `ExpertCouncil` and the CaseReadBatch journal.

The rules stay in force throughout: one ledger, every catch logged, never delete, privacy and consent unchanged, no new dependency.

## Torrent-engine ideas (owner, 2026-11-23: "yes do all")

| Row | Idea | In the app |
|---|---|---|
| PERF-34 | Pieces carry fingerprints | A content-addressed cache of derived results. Each page, attachment and chunk is fingerprinted, and its OCR text, extracted facts, vectors and verified AI replies are stored under that fingerprint and reused when the same content appears again. AI replies are reused only inside the same case's permission and clearance. The cache is cleared by erasure. |
| PERF-35 | A piece map | Big files are cut into fixed-size pieces with per-piece fingerprints (a Merkle list). When a file has grown or changed, only the changed pieces are read again (mailboxes and watched folders). |
| PERF-36 | Priority pieces (streaming mode) | Documents in the open case, or related to the current question, go to the front of every import or drain queue. |
| PERF-37 | Endgame mode | When few items remain, idle workers start a duplicate of the slowest local item and the first result wins. On-Mac work only, never AI calls. |
| PERF-38 | Choking: favour the fastest peers | Reading concurrency is set per disk, by measured throughput (SSD wide; USB, network or optical narrow). |
| PERF-39 | Many peers at once | Read from the fastest available copy of the same bytes (the sealed vault on SSD vs the original on a slow volume), verified by fingerprint. |
| PERF-40 | A swarm | For a team case, team Macs share a big import through the team folder. Each claims pieces of work (leases), processes them and publishes signed, encrypted partial databases, which the others merge (ShardMerger). The owner approved it on 2026-11-23. It stays a per-case opt-in, shown to every member. |
